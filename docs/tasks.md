# Claude Code 작업 순서

AI 담당 · AI(판정 엔진·AI 기능) · 11/5 ~ 12/1

판정 엔진을 Claude Code와 함께 단계별로 만든 작업 기록이다. 각 단계에 Claude Code에 넣은 프롬프트와 담당자가 직접 확인할 것을 적는다. 팀 내부용 문서이며, 서비스 소개는 [루트 README](../README.md)와 [기획서](proposal.md)를 본다.

## 진행 방법

1. 아래 단계의 프롬프트를 Claude Code에 **그대로** 붙여넣는다.
2. 끝나면 "내가 확인할 것"을 직접 점검한다. 설명이 안 되면 다음 단계로 가지 않는다.
3. 커밋됐는지 확인하고 다음 단계로 간다.

한 단계가 끝나기 전에 다음 프롬프트를 넣지 않는다. 이 엔진은 PT에서 내가 직접 설명해야 하니, 속도보다 이해가 우선이다.

각 단계는 [docs/proposal.md](proposal.md) 12장의 작업 ID(P1~P12)와 연결된다. 룰과 입출력의 기준은 [docs/spec.md](spec.md)다.

## 단계 0. 시작 준비 (11/5, 20분)

1. 이 폴더(`kkam-engine`)를 작업할 위치에 둔다. (당시에는 엔진 단독 저장소였다. 지금은 모노레포의 `engine/` 폴더다.)
2. 터미널에서 `java -version`을 실행한다. 17 이상이 아니면 Claude Code를 켠 뒤 "JDK 17 설치 도와줘"라고 한다.
3. `cd kkam-engine` 후 `claude`를 실행한다.
4. 첫 프롬프트:

```
CLAUDE.md, docs/proposal.md, docs/spec.md, docs/tasks.md를 읽고
1. 이 서비스가 뭔지 3줄로,
2. 내가(AI 담당) PT까지 만들어야 하는 것을 proposal.md 12장 기준으로 5줄로,
3. 이번 주(~11/11)에 할 일을 3줄로 요약해줘.
코드는 아직 만들지 마.
```

5. **팀 공유**: `docs/spec.md`의 2장(입출력 형식)을 팀 단톡방에 올린다. 앱 담당에게는 에뮬레이터에서 핸들 각도와 TBT 남은 거리가 나오는지, 서버 담당에게는 EVENT 형식으로 저장할 수 있는지 확인을 부탁한다.

**내가 확인할 것**: 요약에 "순수 Kotlin 라이브러리", "R1 상태 머신", "시나리오 테스트"가 들어 있는가.

## 단계 2. 데이터 모델 (11/6)

```
docs/spec.md 2장대로 입출력 데이터 클래스를 kkam.engine.model 패키지에 만들어줘.
- 입력: SignalFrame, Tbt, TrafficLight, 그리고 enum Gear, TurnSignal, TurnType, LightPhase
- 출력: sealed interface EngineOutput 아래 Guide, Event. Event의 result는 enum Result(KEPT, MISSED), rule은 enum RuleId(R1, R2, R3)
- 모두 @Serializable. JSON의 "type" 필드 값("GUIDE", "EVENT")으로 Guide와 Event를 구분하게 해줘.
- spec 2장의 예시 JSON 3개(입력 1개, 출력 2개)를 파싱하는 테스트를 추가하고 통과시켜줘.
- Kotlin의 data class, sealed interface, nullable 타입(?)을 Java와 비교해서 짧게 설명해줘.
```

**완료 기준**: 예시 JSON 파싱 테스트 통과, 커밋.

**내가 확인할 것**: `steeringDeg`, `tbt`, `light`가 왜 nullable인지 spec을 보고 설명할 수 있다.

## 단계 11. 모드 입력 추가, spec v0.4 (11/15~16) · P6

```
docs/proposal.md 4.3(모드)과 12장 P6를 보고 docs/spec.md를 v0.4로 고치는 안을 먼저 보여줘. 코드는 내 확인 후에.
- Engine을 만들 때 CoachingConfig를 받는다: mode(DIAGNOSE, CORRECT, TRAINING, QUIET), selectedRules(교정 모드에서 안내할 룰), 룰별 guideEvery(1이면 매번, 2면 두 번에 한 번, 0이면 끔)
- 모드별 GUIDE: DIAGNOSE·QUIET는 없음, CORRECT는 selectedRules만, TRAINING은 전부. EVENT는 모든 모드에서 기록.
- guideEvery가 2면 그 룰의 안내 기회를 1번째, 3번째, 5번째...에만 안내. 랜덤 쓰지 마.
- GUIDE를 안 내보냈으면 EVENT의 guided는 false.
- 엔진 실행 중에 config를 바꿀 수 있게 updateConfig()도 둬.
- 시나리오 파일에 config 필드를 추가하고, 없으면 TRAINING으로 본다.
- R4·R5(spec v0.2)는 안내를 따랐을 때만 EVENT가 나오는 룰이다. GUIDE를 끄는 모드에서 R4·R5를 어떻게 다룰지 선택지를 같이 보여줘.
```

spec을 확인한 뒤:

```
spec v0.4대로 코드와 기존 시나리오를 고쳐줘. 그리고 S2와 같은 주행을 모드만 바꿔 4개(DIAGNOSE, CORRECT+R1 선택, CORRECT+R1 미선택, QUIET) 시나리오로 추가하고 통과시켜줘.
```

**완료 기준**: 모든 시나리오 통과, 커밋. 앱 담당에게 config 사용법 공유.

**내가 확인할 것**: 진단 모드에서 GUIDE가 안 나오는데 EVENT는 나오는 이유를 서비스 관점(proposal 4.1)으로 설명할 수 있다.
