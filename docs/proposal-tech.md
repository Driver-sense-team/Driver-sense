# Driver Sense 기술·AI 활용 (초안)

작성 2026-11-05, 수정 2026-11-11 · AI 담당 → PM · 접수양식 **5. 개발 계획**(Pleos Connect 구현 방식, 주요 개발 범위, SDK/API 사용계획)에 옮겨 쓴다.

> 이 문서는 11/11 기준 요약이다. 이후 R2·R3·R6·R7과 시나리오 S13~S24가 추가돼, 엔진은 지금 R1~R7을 판정한다. 3장의 수치와 5장의 일정은 작성 당시 값이다. 현재 범위는 [engine/README.md](../engine/README.md), 서비스 전체는 [proposal.md](proposal.md)를 본다.

## 1. 구현 방식: 판정은 규칙으로, 설명과 개인화는 AI로

법규 판정에 LLM을 쓰지 않는다. 판정은 법 조항과 1:1로 대응해야 근거를 설명할 수 있고, 같은 주행에는 언제나 같은 결과가 나와야 검증할 수 있다. 회전 수십 미터 앞에서 안내하려면 응답을 기다릴 시간도 없다. 그래서 판정은 차 안에서 상태 머신으로 즉시 처리하고, LLM은 주간 코칭과 법규 Q&A처럼 판정 결과를 사람의 말로 바꾸는 곳에만 쓴다. Q&A는 확인된 법규 룰 테이블 안에서만 답하고, 코칭은 입력에 없는 숫자를 만들지 못하게 제한한다.

판정 엔진은 Android에 의존하지 않는 순수 Kotlin 라이브러리다. 앱과 서버가 같은 코드를 쓸 수 있고, 차량이나 에뮬레이터 없이 모든 판정을 자동으로 시험할 수 있다.

## 2. 판정 룰

### 회전 전 방향지시등 (R1)

도로교통법 제38조와 시행령 별표 2는 회전 지점 30m 전(고속도로 100m)부터 방향지시등을 켜도록 정한다. 엔진은 이 규정을 세 단계로 처리한다.

1. **감시**: 내비의 다음 회전이 100m 안으로 들어오면 추적을 시작한다.
2. **예방**: 방향지시등이 꺼져 있으면 판정 지점 약 4초 전(초기값)에 한 문장으로 한 번 안내한다. 속도가 빠를수록 일찍 안내한다.
3. **판정**: 30m 지점에서 방향지시등을 확인해 기억하고, 진행 방향이 60° 바뀌어 실제 회전이 확인되면 기록한다.

경로가 바뀌거나, 회전하지 않았거나, 주차·후진하면 기록 없이 취소한다. 신호 대기 시간은 제외해 교차로에서 오래 기다려도 판정이 유지된다.

### 나들목 깜빡이 (R4)와 터널 전조등 (R5)

내비 안내가 나들목 진출입이면 약 4초 전에 깜빡이를, 터널이면 200m 앞에서 전조등을 안내한다. 안내를 듣고 켜면 지킴으로 기록한다. 차로 번호와 터널 통과 여부는 차량 신호로 알 수 없어서, 이 두 룰은 놓침을 기록하지 않고 예방 안내에 집중한다. 전조등이 자동(AUTO)이거나 이미 켜져 있으면 안내하지 않는다.

## 3. 검증 방법과 결과 (11/11 기준)

정상·위반·예외 주행을 JSON 시나리오로 만들고, 엔진 출력이 기대값과 정확히 같은지 자동으로 비교한다. PT 데모도 같은 시나리오 파일을 재생한다.

- 시나리오 12개 통과: 정상, 위반, 반대쪽 방향지시등, 경로 재탐색, 신호 대기, 주차, 회전 취소, 터널, 나들목
- 엔진 테스트 56개, 앱 테스트 85개 통과
- 규칙을 일부러 망가뜨렸을 때 테스트가 실패하는지 6가지 경우로 확인

Pleos Connect Emulator에서 앱이 엔진을 실행해 안내 음성, 주행 화면 코치 카드, 내비 위 안내 카드, 정차 리포트까지 동작하는 것을 확인했다. 에뮬레이터의 내비는 위치가 움직이지 않아 주행 장면은 녹화된 차량 신호를 재생해 보여준다. 엔진은 실제 신호와 재생 신호를 똑같이 처리한다.

## 4. Pleos SDK 사용 계획

| SDK | 용도 |
| --- | --- |
| Vehicle SDK | 방향지시등, 기어, 브레이크, 핸들, 전조등(하향등). 판정의 핵심 신호 |
| AAOS 차량 속성 | 속도. 안내 시점 계산과 정지 판정 |
| NaviHelper SDK | 다음 안내(회전, 나들목, 터널)와 남은 거리(TBT). 안내·판정 시점 계산 |
| FusedLocation SDK | 위치, 진행 방향. 회전 완료 판정과 리포트 지도 |
| TextToSpeech SDK | 주행 중 예방 안내 음성 |
| SpeechToText SDK | 음성 법규 질문 |

법규 Q&A는 지금 법규 룰 테이블의 키워드 매칭으로 답하고, 근거 조항을 함께 보여준다. 주간 코칭과 자연어 Q&A에는 LLM을 붙인다. LLM은 Pleos LLM SDK를 우선 쓰고, 차량이나 에뮬레이터에서 쓸 수 없으면 팀 서버에서 외부 LLM을 호출한다. 어느 경우든 답은 룰 테이블 근거 안에서만 만든다.

차종별로 지원 기능이 다를 수 있어 `checkXXXCapability`로 확인하고 지원되는 룰만 켠다.

## 5. 주요 개발 범위와 계획

| 시기 | 범위 |
| --- | --- |
| 1차 제출까지 (완료) | 판정 엔진 R1·R4·R5, 앱 연결(음성 안내, 주행 코치 카드, 내비 위 안내 카드), 시나리오 재생 데모, 정차 리포트, 진단·습관 선택·모드 설정·법규 Q&A·교정 진행 화면 (진단·교정 진행 수치는 데모 데이터) |
| ~11/23 | 모드 입력 연결, 적색 신호 우회전 일시정지(R3), 깜빡이 없이 회전(R2), 판정 기록 서버 저장 |
| ~11/28 | 적응형 안내·습관 졸업, 습관 패턴 분석, 주간 코칭·Q&A 프롬프트와 평가 |
| ~12/2 | 앱·서버 통합, PT 데모 시나리오, 리허설 |

습관 패턴 분석은 룰별·시간대별 준수율, 자주 놓치는 곳, 안내 후 준수 전환율을 계산한다. Q&A는 평가 질문 20개 중 18개 이상 정답, 근거 표시 100%를 기준으로 검증하고, 코칭은 샘플 5개에서 생성된 숫자가 입력과 모두 일치하는지 확인한다.
