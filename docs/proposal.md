## 1. 서비스 개요

| 항목 | 내용 |
| --- | --- |
| 서비스명 | Driver Sense |
| 한 줄 소개 | 차 안에 나만의 선생님. 차량 신호로 운전 법규 습관을 진단하고, 고칠 습관만 골라 미리 알려주는 차량용 앱 |

## 2. 문제 정의

### 2.1 현황

| 지표 | 수치 |
| --- | --- |
| 교차로 좌회전 시 방향지시등 점등률 (2025 교통문화지수) | 75.7% (4대 중 1대는 안 켬) |
| 안 켜는 이유 1~3위 | 주변에 차가 없어서 40.0%, 신호·지정차로라 필요 없어서 24.3%, 귀찮아서 15.1% |
| 방향지시등 관련 공익신고 (2023~2025) | 149만 7,280건 |
| 현장 적발 범칙금 (2023~2025) | 10만 4,131건, 약 29억 2,000만 원 |
| 방향지시등 미사용 처분 (승용차) | 현장 적발 범칙금 3만 원, 공익신고 과태료 4만 원 |
| 벌점 신설 | 미사용 시 벌점 10점, 입법예고 완료, 이르면 2027년 중순 시행 |
| 집중 단속 | 2026년 10월 1일~12월 31일, 방향지시등 등 기초 법규 |
| 적색 신호 우회전 미정지 | 범칙금 6만 원, 벌점 15점. 2026년 4~6월 전국 집중 단속 |

### 2.2 문제의 본질

- 깜빡이를 안 켜는 이유 상위 3개는 모두 "알지만 안 하는" **습관** 문제다.
- 처벌은 강해지는데(집중 단속, 벌점 신설 예정) 습관을 고쳐주는 도구는 없다.
- 위반을 알게 되는 시점이 너무 늦다. 공익신고 과태료는 위반 후 한참 뒤에 고지서로 온다. 그 순간에 알려주는 피드백이 없다.
- 폰 기반 운전 점수 앱은 GPS와 가속도 센서만 쓴다. 깜빡이를 켰는지, 정지선에서 멈췄는지 알 수 없다.

### 2.3 운전자 Pain Points

| 대상 | Pain Point | Driver Sense의 해결 |
| --- | --- | --- |
| 기존 운전자 | 알지만 습관적으로 안 켠다 | 고른 습관만 위반 직전에 한 문장으로 알려줌 |
| 기존 운전자 | 잔소리하는 앱은 싫다 | 처음 2주는 조용히 진단만, 잘 지키면 안내 감소·졸업 |
| 기존 운전자 | 단속·신고를 당해야 안다 | 주차 후 리포트로 "단속됐다면 받을 처분"을 바로 보여줌 |
| 초보 운전자 | 깜빡이를 언제 켜야 할지 감이 없다 | 연수 모드: 모든 회전에서 거리 기준으로 미리 안내 |
| 초보 운전자 | 적색 신호 우회전 규칙이 헷갈린다 | 적색일 때 접근하면 "멈췄다 가세요" 안내, 음성 Q&A |

## 3. 타깃 사용자

### 3.1 세그먼트

| 구분 | 기존 운전자 (1차) | 초보 운전자 (2차) |
| --- | --- | --- |
| 상황 | 출퇴근·업무로 매일 운전 | 면허 1~2년 이내, 장롱면허 |
| 문제 | 규칙은 알지만 습관적으로 생략 | 규칙이 헷갈리고 타이밍 감이 없음 |
| 원하는 것 | 범칙금·벌점 피하기, 귀찮지 않은 앱 | 안심, 연수 |
| 앱의 역할 | 습관 교정 트레이너 | 연수 선생님 |
| 시작 모드 | 진단 모드 | 연수 모드 |

### 3.2 페르소나 (가상 예시)

- **A. 40대 영업직**: 업무용 그랜저로 하루 2시간 운전한다. 블랙박스 공익신고로 과태료를 받은 적이 있다. 잔소리하는 앱은 바로 지운다.
- **B. 20대 사회초년생**: 첫 차로 아반떼를 샀다. 적색 신호 우회전에서 멈춰야 하는지 매번 헷갈린다.

두 페르소나의 차종이 현재 Pleos Connect 앱마켓 이용 차종과 겹친다.

## 4. 솔루션

### 4.1 핵심 흐름: 진단 → 교정 → 유지 → 졸업

1. **진단 (첫 2주)**: 안내 없이 기록만 한다. 상황별 준수율을 측정한다.
2. **교정**: 사용자가 고칠 습관 1~2개를 고른다. 고른 습관만 위반 직전에 음성으로 안내한다.
3. **유지**: 최근 10회 중 9회 이상 지키면 안내를 두 번에 한 번으로 줄인다.
4. **졸업**: 유지 상태를 3주 연속 이어가면 그 습관은 안내를 끄고 기록만 한다.

초보 운전자는 1~2 대신 연수 모드로 시작해 모든 룰을 안내받고, 같은 유지·졸업 단계로 넘어간다.

### 4.2 사용자 시나리오 (기존 운전자, 출근길)

1. 출발하면 화면은 평소처럼 내비가 전체를 차지하고, Driver Sense는 뒤에서 차량 신호만 본다. 오늘 고치는 습관은 "좌회전 깜빡이"다.
2. 좌회전 50m 전, 깜빡이가 꺼져 있다. 내비 위에 작은 주황 카드가 뜨고 "좌회전 곧이에요, 깜빡이 켜세요." 한 문장이 나온다.
3. 운전자가 깜빡이를 켜고 30m 지점을 지난다. 카드가 파란색 "좋아요"로 바뀌고 몇 초 뒤 사라진다. 화면은 다시 내비만 남는다.
4. 다음 교차로는 적색 신호 우회전이다. "전방 적색이에요, 정지선에서 멈췄다 가세요."
5. 회사 주차장에서 기어를 P로 바꾸면 Driver Sense가 전체 화면으로 올라와 오늘 주행 리포트를 보여준다. 지킨 곳과 놓친 곳이 지도에 찍히고, 각각 법 조항과 처분이 보인다.
6. "왜 우회전할 때 멈춰야 해?"라고 물으면 AI가 법 조항 근거로 답한다.
7. 일요일 저녁, 주간 코칭이 온다. "이번 주 좌회전 11번 중 10번 켰어요. 놓친 1번은 D 삼거리였어요. 다음 주엔 여기만 미리 알려드릴게요."

### 4.3 모드

> **바뀐 점**: 앱에서는 아래 4개 모드를 **운전 코치 켬/끔** 하나로 줄였다. 켬은 안내와 기록을 모두 하고, 끔은 안내만 멈추고 기록은 남긴다. 진단·교정·유지·졸업 흐름(4.1)은 판정 기록으로 이어간다.

| 모드 | 대상 | 주행 중 안내 | 판정 기록 |
| --- | --- | --- | --- |
| 진단 (DIAGNOSE) | 기존 운전자, 첫 2주 | 없음 | 전부 |
| 교정 (CORRECT) | 기존 운전자 | 고른 습관만 (적응형 빈도) | 전부 |
| 연수 (TRAINING) | 초보 운전자 | 모든 룰 | 전부 |
| 조용 (QUIET) | 누구나 | 없음 | 전부 |

### 5.4 주행 중 운전 방해 방지 원칙

- 주행 중(기어 D) 화면 터치 조작 없음. 코치 카드는 표시만 한다.
- 음성 안내는 한 문장. 같은 회전 지점에서 한 번만 말한다.
- 위반 직후에는 잔소리하지 않는다. 지적은 정차 후 리포트에서만 한다.
- 리포트, 습관 선택, Q&A 화면은 기어 P에서만 연다. 주행 중 Q&A는 음성으로만 답한다.

### 5.5 PT 데모 흐름 (3분)

1. 진단 리포트: "좌회전 깜빡이 62%, 전국 평균보다 낮아요" (데모 데이터)
2. 습관 선택: 좌회전 깜빡이
3. 시나리오 재생: 좌회전 50m 전 안내 → 깜빡이 켬 → 지킴
4. 적색 신호 우회전: 안내 → 정지선 정지 → 지킴
5. 주차: 주행 리포트, 아낀 범칙금, 음성 질문 "왜 우회전할 때 멈춰야 해?"
6. 같은 구간을 연수 모드로 짧게 재생

화면 구성: 왼쪽은 주행 상황(지도, 차량 신호 값), 오른쪽은 앱 화면.

> **바뀐 점**: 에뮬레이터 내비는 위치가 움직이지 않아서, 앱에 시연용 경로 데이터를 재생하는 "경로 데모"를 만들었다. 목적지 검색 → 경로 미리보기(내비처럼 예상 소요 시간·거리·도착 시각) → 출발 → 좌회전·적색 우회전·차선 변경(오른쪽 차로로)·비(와이퍼·김서림)·터널·나들목·우회전·유턴·회전교차로(진입·진출) 안내와 판정 → 도착 후 경로 리포트 → "AI에게 묻기" 순서로 4분 가까이 걸린다. 유턴·회전교차로는 판교 청계산로의 실제 회전교차로를 지나도록 끝부분을 넣었다(유턴 위치는 데모 값). 급정거·1차로 정속 주행·깜빡이 뒤 이동 타이밍·커브와 진출로 감속·진출 직후 차로 이동·브레이크 타이밍은 차량 신호에 차로 번호가 없거나 기준이 아직 없어 판정하지 않고, 영상용 각본 안내(카드와 음성)로만 보여준다. 깜빡이를 늦게 켠 좌회전은 실제 R1 판정(놓침)이다. 앱 안 지도가 내비 역할을 한다. 자세한 내용은 [app/README.md](../app/README.md#경로-데모).

## 6. 차량특화성 (심사 기준 1)

**폰 앱은 깜빡이를 켰는지, 정지선에서 멈췄는지 모른다. 차는 안다.**

| 비교 | 폰 운전 점수 앱 | Driver Sense |
| --- | --- | --- |
| 데이터 | GPS, 가속도 센서 | 방향지시등, 핸들, 브레이크, 기어, 내비 다음 회전(TBT), 진행 방향 |
| 판정 단위 | 급가속·급감속 추정 | 법 조항 단위 (30m 전 깜빡이, 적색 우회전 정지) |
| 개입 시점 | 주행 후 점수 | 위반 전 예방 안내 |
| 맥락 | 주행·정차 구분 없음 | 주행 중 음성 한 문장, 정차(기어 P) 후 화면 |

**주행·정차 맥락 활용**

- 기어 P 전환을 신호로 리포트를 연다.
- 내비 TBT의 남은 거리로 "50m 전 안내, 30m 판정" 타이밍을 맞춘다.
- 주행 중에는 내비를 그대로 두고 앱은 뒤에서 동작한다. 안내가 필요한 순간에만 내비 위에 작은 카드를 띄웠다가 지우므로 길 안내를 오래 가리지 않는다.
- 주행이 끝나 기어가 P가 되면 전체 화면 리포트로 바뀐다.

## 8. 기술 구조와 SDK 활용 (심사 기준 3)

### 8.1 구조

```
[Pleos SDK]                     [차량 앱 · Kotlin]                          [서버 · Spring]

NaviHelper ───┼──── 차량 신호 ──▶ 판정 엔진 (AI 담당) ──── EVENT ──────────▶ 이벤트·리포트 API (서버 담당)

                                  │      └─ 교차로 신호 ◀── 신호 프록시·캐시 ◀── 공공 신호등 API
```

### 8.5 데이터와 개인정보

- 위치·주행 기록은 명시적 동의 후에만 수집한다. 동의하지 않으면 판정과 안내만 차 안에서 동작하고 서버에 올리지 않는다.
- 수집 항목은 판정 이벤트(룰, 결과, 시각, 위치)로 최소화한다. 원시 신호 프레임은 서버에 올리지 않는다.
- 보관 기간을 정해 지난 기록은 삭제한다. [보관 기간: 서버 담당 제안 후 확정]
- B2B(보험 등) 제공은 별도 동의를 받고, 개인 식별 정보 없이 지표로만 제공한다.
- 판정 결과는 법적 판정이 아닌 코칭용 기록임을 고지한다.

### 8.6 검증 방법

- **시나리오 테스트**: 정상·위반·오탐 주행을 JSON으로 만들고, 엔진 출력이 기대값과 정확히 같은지 자동 테스트한다. PT 데모도 같은 시나리오 파일을 재생한다.
- **Q&A 평가셋**: 질문 20개(쉬운 것 10, 헷갈리는 것 6, 근거 없는 것 4)로 정답률과 근거 표시율을 잰다.

### 9.2 시장 규모 산정 방식

- Pleos Connect는 2026년 5월 신형 그랜저에 처음 적용됐고, 2030년까지 약 2,000만 대 적용이 목표다.
- 예상 MAU = 국내 Pleos 탑재 차량 수 × 앱 설치율 × 월 활성률
- [국내 Pleos 탑재 누적 대수: PM 리서치]
- [설치율·활성률 가정: PM, 비슷한 차량 앱 사례 근거]
- [초보 운전자 규모: 도로교통공단 운전면허 통계]

### 9.3 핵심 지표 (KPI)

| 지표 | 정의 | 의미 |
| --- | --- | --- |
| 안내 후 준수 전환율 | 안내가 나간 판정 중 지킨 비율 | 예방 안내가 실제로 위반을 막는가 (핵심 효과) |
| 습관 개선폭 | 교정 4주차 준수율 − 진단 기간 준수율 | 습관이 실제로 바뀌는가 |

| 4주 리텐션 | 설치 4주 후에도 활성인 비율 | 지속 사용 |

[목표치: PM이 근거와 함께 기입]

### 9.4 재사용 장치

- 출퇴근·업무 운전마다 자동으로 동작한다. 따로 켤 필요가 없다.
- 주간 코칭, 습관 연속 기록, 아낀 범칙금 누적으로 다시 연다.
- 법 개정·집중 단속 소식을 알린다 (예: 방향지시등 벌점 신설 예정).
- 습관 졸업 배지, 초보 졸업 배지.

### 9.5 확장 로드맵

1. 보호자 리포트, 초보 졸업 시스템
2. 어린이보호구역 감속
3. ADAS SDK 연동: 차가 인식한 신호등·차선·보행자로 판정 고도화 (차로 변경 깜빡이, 횡단보도 보행자 보호)
4. 보험사 안전운전 특약 연계, 법인 차량 관리
5. 주행 행동 분류 모델, 고령 운전자 모드

## 12. AI 담당 할 일

### 12.1 담당 범위

"차량 신호와 판정 기록으로 판단하는 모든 것"이다. 기능으로는 F1(판정 엔진), F3(적응형 안내), F6(졸업 판정), F5·F7(습관 인사이트), F7·F8(LLM 프롬프트), F9(데모 시나리오)를 맡는다. 모든 코드는 이 저장소의 순수 Kotlin 라이브러리로 만들고, 앱(앱 담당)과 서버(서버 담당)가 가져다 쓴다. LLM 호출 자체는 앱에서 하고, 여기서는 LLM에 보낼 프롬프트를 만드는 것까지만 한다.
